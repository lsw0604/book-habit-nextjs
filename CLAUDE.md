## Commands

```bash
npm run dev     # http://localhost:4000 (custom port, not 3000)
npm run build
npm run lint
```

No test runner is configured in this repo (no `test` script, no test files).

Backend is a separate NestJS service; do not assume it's running. Its API contract is Swagger at
`http://localhost:3000/api-json` (see `docs/api-mapping.md` for the FSD-layer mapping of all
endpoints already worked out).

## Architecture

The FSD layer rules (features vs. entities placement, import direction, path conventions) live in
`docs/architecture.md` and are authoritative — read it before placing any new file. The rest below
is the supporting plumbing those rules assume.

### API client: two axios instances, one wrapper

`src/shared/api/core/`:
- `apiClient` (`apiAxiosInstance`) — general authenticated calls; the response interceptor
  (attached from `app/_providers`, not from `shared`, so `shared` never knows about routing)
  retries once after a 401 triggers a token refresh.
- `authClient` (`authAxiosInstance`) — only for `login` / `signup` / `kakao/callback` / `refresh`.
  No interceptor, specifically so a failed `refresh` can't recursively trigger another refresh.
  `me` / `logout` go through `apiClient` since a session already exists at that point.
- Both instances are wrapped by `createApiWrapper` (`wrapper.ts`), which unwraps the backend's
  `ResponseDTO<T>` envelope and normalizes every failure into `APIError` (see `shared/api/types`)
  so nothing above `shared/api` ever touches axios or raw error shapes directly.

### Data fetching

TanStack Query everywhere except one intentional exception documented in `docs/architecture.md`
(`views/public-feed`, RSC-only, for OG preview on link shares). No Server Actions — the NestJS
backend already owns the API contract, so Server Actions would create a duplicate server layer.

Query keys are centralized per entity via `@lukemorales/query-key-factory`
(e.g. `src/entities/book/api/query-key.ts`, `src/entities/user/api/query-key.ts`). A
feature's mutation must invalidate through the owning entity's key factory rather than
constructing/duplicating the key itself — this is what lets `docs/architecture.md` rule 3
("features 간 직접 참조 금지") hold for cross-feature cache invalidation.

Search-type features share `shared/lib/use-debounced-query.ts` for debounce + URL query sync
instead of each reimplementing it — this is a pre-approved shared/lib exception to the
"features don't share code with features" rule.

### Auth

`app/_providers` wires three providers (`api-provider`, `auth-provider`, `query-provider`).
`auth-provider` owns the refresh-and-retry callback wiring that gets injected into the
`apiClient` interceptor. Server-side cookie reads for auth live in
`src/shared/api/server/server-auth.ts` (uses `next/headers`; this is the one place in
`shared/api` allowed to know it's running on Next).

### Next.js portability constraint (read `docs/portability.md` before touching routing/env/links/images)

This app is planned to be reimplemented later as a Vite SPA for a framework comparison, which
constrains how a few cross-cutting concerns are written *today*:
- Framework-specific APIs (`next/link`, `next/image`, `useRouter`/`usePathname`/`useSearchParams`,
  `next/headers`) are meant to be confined to adapter files
  (`shared/ui/link.tsx`, `shared/ui/image.tsx`, `shared/lib/use-navigation.ts`) plus
  `shared/config/env.ts` for env vars — but this is aspirational, not yet enforced: several
  `features`/`entities` files currently import `next/navigation` / `next/link` / `next/image`
  directly (e.g. `features/search-book/ui/*`, `entities/book/ui/book-card-thumbnail.tsx`). When
  touching these, prefer routing new usages through the adapters rather than adding more direct
  imports, but don't treat existing direct imports as a bug to fix opportunistically.
- `docs/portability.md` has the full rationale and a check command:
  `grep -rn "from ['\"]next/" src/shared src/entities src/features`.

### AGENTS.md file regeneration

The "This is NOT the Next.js you know" block at the top of `AGENTS.md` is regenerated by
`next dev` (see `node_modules/next/dist/server/lib/generate-agent-files.js`). Don't try to
permanently delete it — removing it just recreates an uncommitted diff on the next dev run.
